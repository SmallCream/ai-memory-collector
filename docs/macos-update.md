# macOS 双击更新插件

适用于已经通过“加载已解压的扩展程序”安装 AI Memory Collector 的 Mac 用户。取得兼容当前扩展版本的更新脚本后，日常更新不用重复下载 ZIP、解压或手工覆盖文件。

脚本只在你运行时工作，不安装服务，也不会自动操作浏览器。每次完成后，仍需在扩展管理页点一次“重新加载”。Windows 暂不支持此脚本。

## 从旧 P0 更新器升级

0.2 之前下载的更新器只接受 `AI Memory Collector · P0` 这个扩展名称。0.2 名称变为 `AI Memory Collector`，因此旧脚本会拒绝该版本，即使代码下载成功也不会安装。

需要一次性用新版 `update-macos.command` 替换你保留的旧脚本。新版对白名单中的旧、新名称都兼容；只替换更新脚本，仍使用浏览器原来加载的 `extension` 文件夹，不卸载、不重新安装插件。原目录记忆和浏览器存储继续沿用；如重新询问目录，选择原加载路径。

**0.4.10 更新器默认跟随 `main`，显式添加 `--test` 才使用开发测试分支。** 旧脚本不识别该选项，需要先替换脚本本身。测试渠道每次运行均需指定，不会悄悄改变以后双击更新的来源。

## 第一次使用

1. 按渠道取得更新器：使用 main 时下载 [main 源码 ZIP](https://github.com/SmallCream/ai-memory-collector/archive/refs/heads/main.zip)；使用当前开发版时下载 [测试分支源码 ZIP](https://github.com/SmallCream/ai-memory-collector/archive/refs/heads/feat/automatic-collector-v2.zip)。解压后取得更新器，不需要加载解压出的新插件。main 中的脚本可能尚未包含测试分支的新选项。
2. 找到根目录的 **`update-macos.command`**。可以把它单独放到桌面等方便的位置，后续继续使用这一个文件。
3. 按下文“更新前准备”停止新增任务，等待当前写入及独立传输结束，再关闭采集台。
4. 双击 `update-macos.command`，会打开终端并弹出文件夹选择窗口。
5. 选择**浏览器原来加载的 `extension` 文件夹**，其内部应直接有 `manifest.json`。也可以选择它的上层代码仓库目录，脚本会定位其中的 `extension`。
6. 等待终端显示检查或更新结果。更新成功后，Chrome 打开 `chrome://extensions`，在 AI Memory Collector 卡片上点“重新加载”；Edge 对应 `edge://extensions`。
7. 刷新已打开的来源平台页，再从工具栏图标打开采集台，按“更新后核对”检查。

**不要把刚下载的新目录当作原安装目录，也不要卸载重装。** 脚本不会查看浏览器资料来猜测安装位置，你第一次选择的路径必须与浏览器已经加载的位置一致。选择文件夹时可以取消，不会更新。

如果双击提示文件没有执行权限，可以打开“终端”，输入 `bash `（末尾留一个空格），将 `update-macos.command` 拖入终端，再按回车。不需要 `sudo`，不需要安装 Git、Node 或 Python。

## 更新前准备

**收起或关闭面板不会停止后台任务。更新器只管理代码文件，不读取浏览器任务状态，也不会代你暂停任务。**

1. 在设置记下当前开关，暂时关闭自动采集、本地附件自动下载，以及已启用的 GitHub 自动上传和自动恢复；等待设置保存完成。没有启用的功能保持关闭。
2. 有进行中的对话任务时，返回首页点击“停止本轮”，等待显示已停止。已经完成的任务不必重新启动。
3. 展开“附件下载详情”或“下载与上传详情”，确认没有进行中的手动附件补齐／重试、GitHub 备份或仓库恢复。这些任务独立运行；“停止本轮”不代表它们全部停止。若仍在传输或写入，等当前操作结束；有待恢复写入时先按提示处理。
4. 记下设置中显示的扩展版本、账号及归档目录，保留原代码备份和独立的归档备份，再运行更新器。

## 以后怎么更新

1. 完成上面的更新前准备。
2. 使用 main 时双击保留的 `update-macos.command`；测试版每次运行都要添加 `--test`，具体命令见下文。
3. 若提示更新成功，到扩展管理页点“重新加载”，刷新来源页，再打开采集台。

原目录存在且有效时，不会再次询问目录。代码没有变化时不重复替换或覆盖备份。网络请求失败或下载的文件不符合要求时，脚本报错并保留原版，恢复网络后再次运行即可。

若文件替换过程中异常中断，脚本会保留恢复记录；下次运行时，如果原目录缺失且备份有效，会先恢复原代码再继续。

默认来源为本公开代码仓库的 `main`；`--test` 来源为 `feat/automatic-collector-v2`。终端显示所选渠道和提交编号，然后下载该提交的不可变源码快照，仅安装 `extension`，不需要 GitHub Token。两个渠道都拒绝低于已安装版本的代码；返回 main 时若版本较低会停止，不会自动降级。需要回退时单独使用原代码备份的 `--rollback`。main 和测试分支都不等同于已验收的稳定发布，更新成功也不等于所有功能已经验证。

## 更新后核对

- 设置页版本与更新器显示的目标版本一致，原账号、归档目录和结果仍在。
- 在本地打开一份已有 Markdown，确认正文和已保存图片可读。
- 按更新前记下的值恢复需要的自动开关。已“停止本轮”的账号需要主动点击首页“检查更新”开始新一轮；恢复开关本身不会复活已停止队列。
- 首页“检查更新”检查的是**对话变化**，不会升级插件代码。不必为验证升级而执行全量补采。

## 更新失败怎么排查

更新器错误显示在运行它的**终端窗口**，不会进入插件的“问题与诊断日志”。终端退出前保留渠道、当前／目标版本、提交编号及错误文字；若需要反馈，遮去用户名和完整本地路径，不要提交归档或浏览器凭据。

| 终端结果 | 下一步 |
| --- | --- |
| 无法检查版本／下载失败 | 原安装尚未替换；检查网络后用相同渠道重试 |
| 远端版本低于已安装版本 | 核对是否遗漏 `--test`；不要删除版本检查来强行降级 |
| 已是相同代码，无需更新 | 正常结束；不需要全量补采，也没有新增替换备份 |
| 原目录含额外文件或非插件数据 | 先核对并备份这些文件，将归档与代码分开；不要直接删除 |
| 更新未完成，已恢复原插件目录 | 原代码已恢复；处理之前的具体错误后重试 |
| 自动恢复失败 | 保留终端显示的备份和目标路径，停止继续覆盖；核对后将原代码恢复到原路径 |

回退也是代码替换，先执行相同的更新前准备，再使用下面的 `--rollback`。回退成功后重新加载并核对版本、账号和目录；回退不会撤销浏览器内已经发生的数据迁移。

## 设置与文件

| 内容 | 更新器如何处理 |
| --- | --- |
| 原插件目录 | 保持原路径，更新其中的插件代码 |
| 上一个代码版本 | 更新前备份在原目录旁，供回退使用 |
| 仓库、分支、已勾选记住的 Token、暂存 | 位于浏览器扩展存储中，更新器不读取或清理 |
| 对话 JSON、Markdown | 应保存在独立的数据目录，更新器不采集或上传 |
| 原目录位置 | 保存在本机 `~/Library/Application Support/AI Memory Collector Updater` |

同一浏览器配置、同一扩展身份下，原地更新可以继续使用已保存的设置。旧版从未保存过的 Token 仍需填写一次；目录读写权限也可能需要在浏览器再次授权。代码备份不是浏览器数据备份，不能恢复卸载扩展后丢失的设置。

请勿将对话归档或其他个人文件放进 `extension` 代码目录。若脚本发现数据目录或不符合要求的文件，会停止并说明原因。

## 选错目录或需要回退

在终端输入 `bash `，拖入脚本，再添加下面的参数后按回车：

| 参数 | 用途 |
| --- | --- |
| `--test` | 本次使用开发测试分支；可与 `--choose` 组合，不可与 `--rollback` 组合 |
| `--choose` | 重新选择浏览器原来的插件目录 |
| `--rollback` | 将所选目录恢复到最近一次更新前的代码；完成后仍需重新加载扩展 |
| `--help` | 查看脚本说明 |

例如，脚本放在桌面时：

```sh
bash "$HOME/Desktop/update-macos.command" --test
bash "$HOME/Desktop/update-macos.command" --choose
bash "$HOME/Desktop/update-macos.command" --rollback
```

回退只针对插件代码，不回退浏览器内的数据结构或设置。不要在脚本运行时移动安装目录或同时手工修改插件文件。

历史代码备份会保留，不自动清理；终端会显示本次备份路径。连续执行回退会在最近的两个代码版本间切换。

脚本不会自动替换自身。此次 0.2 名称兼容调整需要手动替换一次脚本；完成后，日常插件代码更新继续运行同一新版脚本即可。以后若更新器本身需要升级，会另行说明。
