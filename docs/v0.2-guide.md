# 0.2 使用指南

本指南对应 0.2.0 开发版本。功能已接入代码，真实 ChatGPT 账号、目录权限和 GitHub 端到端流程仍需浏览器验收，不能据此认为所有账号、对话类型都已支持。

## 第一次配置

1. 在桌面 Chrome / Edge 安装或原地更新扩展，打开并登录 ChatGPT，切到个人空间。
2. 点击工具栏采集器图标，进入首次设置；允许访问 `chatgpt.com` 后自动发现页面并识别当前登录身份。
3. 填一个自己容易认出的账号名称，例如“我的主账号”，点击“启用此账号并继续”。名称是展示信息，内部使用稳定账号标识隔离数据，目录采用该标识的哈希，同一账号在不同设备保持一致。
4. 选择一个专用数据文件夹并确认写入权限。之后所有新对话和更新都写入这个目录，不必逐条选择文件，也不必每次更换空目录。
5. 可选：填写私有 GitHub 数据仓库，格式为 `owner/repository`；分支留空使用默认分支。填写仅授权该仓库 Contents 读写权限的 Token，点击验证并连接。选择“稍后配置”则仅本地保存。
6. 检查账号、目录和同步设置，选择是否开启每 30 分钟的自动增量，点击“完成并初始化采集”。

选择目录和首次站点授权需要用户点击。目录权限失效后会出现“恢复保存权限”，按提示确认即可，不需要重复填写所有设置。

## 日常面板

ChatGPT 页面边缘保留悬浮入口，点击展开侧边面板。面板显示当前标签页实际识别出的账号、采集进度、本地保存状态和 GitHub 同步状态。

| 操作 | 用途 |
| --- | --- |
| 收起 | 保留悬浮入口，继续正常聊天，任务不因收起而主动暂停 |
| 隐藏 | 隐藏面板和悬浮入口；从工具栏图标恢复 |
| 立即检查更新 | 立即检查当前账号的新增、更新和待重试对话 |
| 全量补采 | 重新读取当前账号所有可访问普通对话详情，核对和补齐文件 |
| 暂停 / 继续 | 保留检查点，之后接着处理 |
| 设置 | 修改采集间隔、目录和 GitHub 连接 |

不需要选择具体对话、翻列表页或手动选择详情接口。多个同账号标签页共用该账号的任务状态，切换页面不会重复启动任务。非 ChatGPT 页面不显示悬浮入口。

## 初始化、增量与补采

**初始化**会遍历普通列表并读取详情；只有列表和目标详情都成功处理后才记为本轮完成。某条失败时其他可处理对话继续，失败项保留并显示待处理数量。

**增量**默认每 30 分钟检查，设置中可以改为 15 / 30 / 60 分钟。根据已知对话、更新时间及失败记录决定需要读取的详情；对缺失或不可靠的变更信息采用保守重读。每条成功落盘后才推进相应处理状态。

**全量补采**不受上次增量时间范围限制，重新检查全部可访问列表和详情。已有对话按 ID 更新原路径，内容相同就跳过重复写入，缺失的 Markdown 可以重新生成。补采不能恢复线上已删除且此前从未归档的内容。

同一账号一次只执行一个采集任务。运行中的定时触发会合并；全量补采不会和增量同时写同一组文件。

## 自动运行的条件

需要浏览器运行、ChatGPT 标签页可访问、账号已启用且登录有效、本地目录仍有写入权限。浏览器退出或设备休眠期间不能执行；恢复后根据持久状态继续或补做一次检查，不会把错过的所有定时点重复执行。

登录过期、账号切换、目录失权、网站验证或限流时，面板会显示需要处理或等待重试的原因。后台可能被浏览器挂起，因此任务按小步保存检查点，不依赖侧边面板持续打开。时间间隔是检查计划，不保证精确到秒。

## 多账号

新账号第一次出现时需单独启用；启用之后保留各自的初始化状态、检查点和保存目录归属。

仅切换同账号的对话标签页不会切换归档账号。采集所用登录会话实际从 A 变成 B 时，A 的任务暂停；账号核验通过后才处理 B。请求前后身份变化的详情会被丢弃，不写进任一账号目录。

当前工作区仍需按个人空间范围使用。团队空间、项目会话等没有完成验证，不应把界面展示名当作工作区已验证的证据。

## 本地文件与 GitHub

JSON 是主数据，Markdown 由同一份 JSON 生成，默认只呈现方便阅读的对话；分支关系、源标识和元信息保留在 JSON 与清单中。文件写入后核对，任务成功状态与“GitHub 已同步”分别记录。

GitHub 配置完成并启用后会上传真实归档。请使用私有数据仓库，勿填公开的采集器代码仓库。Token 保存在当前浏览器，可以在设置中更换或清除；不会传给 ChatGPT 或写入归档文件。

远端有并发变化时，插件重新读取并比较，使用非强制提交。可靠来源更新时间可以用于选择版本；无法判断或发现人工改动时保留冲突版本并提示，不按本机采集时间盲目覆盖。上传失败保留本地文件和待同步任务，可点击重试。

当前还没有“新电脑下载整个仓库”的恢复入口；多机共同写入与冲突处理需进一步实测。

## 升级旧版本

沿用原加载目录、浏览器配置与扩展身份，覆盖代码后重新加载扩展并刷新 ChatGPT 页面。不要卸载重装，否则浏览器可能删除原扩展存储。

新版沿用旧数据库，恢复原目录句柄、仓库和分支；只有旧版曾明确选择记住的 Token 才能恢复。首次新版引导仍会要求确认账号和是否开启真实对话上传。

旧版 `p0-captures/` 文件不会迁移或删除，新版归档写入 `data/web/`。旧 `pendingArchive` 副本保持在扩展存储中并提示存在，不自动覆盖、上传或清除。请保留旧文件与同一浏览器身份；不要把这项兼容性理解为旧暂存已经迁移到新目录。

如果使用的是 0.2 之前下载的 Mac 更新器，需要一次性用新版 `update-macos.command` 替换旧脚本。旧脚本只接受 P0 扩展名称，新脚本同时识别旧、新名称；替换脚本不会要求卸载插件，继续使用浏览器原来加载的 extension 目录。更新器仍只跟随 `main`：0.2 尚在开发 PR 时，正常运行更新器不会安装它，需要等合并后再更新。参见 [更新指南](macos-update.md)。

## 常见状态

| 状态 | 处理方式 |
| --- | --- |
| 未发现 ChatGPT / 登录失效 | 打开网站并登录，然后继续采集 |
| 新账号未启用 | 确认展示的身份后启用此账号 |
| 需要目录权限 | 点击恢复权限；原文件与任务进度保持 |
| 详情不完整 / 仍在生成 | 等生成结束后重试；平台分页协议不兼容时等待适配更新 |
| 本地文件已被修改 | 保留人工改动；检查对应文件与提示，避免继续手工修改未完成文件组 |
| 本地已保存，GitHub 待同步 | 检查网络、仓库权限和 Token，再重试同步 |
| 部分完成 | 查看待处理数量并继续；不能据此认为所有对话都已归档 |

请勿在代码仓库提交真实对话、Token、Cookie 或完整网络抓包。反馈问题时可以提供版本号、错误码和经过遮蔽的状态截图。
