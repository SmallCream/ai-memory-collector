# 小范围试用操作卡

这是开发测试版。先完成下面的本地备份流程；GitHub 可稍后单独验证。账号中的普通对话可能被全部枚举，不能只选一条采集；首次试用建议使用只有非敏感内容的测试账号和独立空归档目录。

## 第一次备份

1. **安装：** 解压扩展 ZIP 到固定位置，在 Chrome 扩展管理页开启开发者模式，加载含 `manifest.json` 的目录。若拿到外层试用包，需先解压其中的扩展 ZIP。已有安装应按升级流程沿用原路径，不要卸载。
2. **连接：** 在已登录的 ChatGPT 或豆包普通对话页打开采集器，确认平台及账号，点击“启用此账号并继续”。
3. **选目录：** 选择单独的归档目录并授予读写权限；不要选择插件代码目录。点击“仅使用本地备份，继续”。
4. **开始：** 核对账号、目录及自动采集设置，点击“开始首次备份”。初次完成时间取决于账号历史数量，不要求在固定秒数内完成。
5. **看结果：** 分别看对话和附件摘要。去保存目录打开一份 Markdown，并检查一张已下载的图片。对话完成不代表所有附件成功。
6. **再检查：** 不新增或修改对话，点首页“检查更新”。仍扫描列表；没有缺失、失败或旧格式待处理时，正文读取应为 0，已有文件不重写。“检查更新”不会升级插件。

## 卡住时去哪里看

从首页“问题与诊断日志”进入，或点对应的“查看…问题”。确认账号，再按阶段、结果、时间或错误码筛选；“重置筛选”不会删除记录或重试任务。

| 看到的情况 | 先做什么 |
| --- | --- |
| 对话完成，附件仍失败 | 查看附件问题；先确认来源原网页能否打开附件 |
| 日志失败数多于首页问题数 | 日志包含历史步骤；当前待处理数量以首页为准 |
| 当前筛选没有日志 | 重置筛选并核对账号；旧日志可能超过保留期，不能推断没有问题 |
| 目录权限失效 | 在设置恢复原目录权限；不要随意换成新的空目录 |
| 需要中断 | 暂停可继续原队列；“停止本轮”结束旧队列。收起面板不会停止任务，独立手动附件／GitHub 任务需另行等待 |
| Mac 更新脚本失败 | 查看运行脚本的终端；该错误不在插件日志中，按同包更新指南处理 |

需反馈时，先“预览脱敏导出”，检查后保存诊断文件；它导出所选账号和仓库恢复的保留记录，不限于当前筛选。只主动提供检查过的诊断和错误码，去掉截图中的私人内容。不要提交正文、标题、真实文件名、完整本地路径、Token、Cookie、签名链接或 HAR。无需为反馈故意制造失败或重采全部历史。

## 后续验证

- **停止与重启：** 在测试账号存在运行中的队列时点“停止本轮”，等到已停止及当前写入结束，正常退出并重开浏览器。原账号和目录应保留，旧队列不自动继续。未遇到运行队列则记录未执行，不为此重采日常账号。
- **升级：** 收到下一份明确版本的测试包后，按同包 Mac 更新指南／完整流程验收说明操作；保留原路径和扩展身份，核对账号、目录及旧文件。相同版本重复运行是“不变检查”，不能算跨版本升级通过。Windows 使用备份后原路径替换代码，再重新加载的方式；Mac 脚本不适用于 Windows。
- **目录迁移：** 在测试数据上停止新增任务，等待独立传输和写入结束，复制整个归档根目录后在设置选择副本。再检查更新并打开 Markdown／已下载图片；旧目录应保留。新目录缺失时按需“补齐缺失”，不默认全量补采。

用同包的空白验收表记录实际结果、耗时及是否求助。不需要交出测试账号。无样例、未获所需环境或没有执行的步骤均记“未执行”，不要填“通过”。
