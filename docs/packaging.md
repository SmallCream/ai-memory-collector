# 打包、渠道与发布边界

当前仍为开发测试版，设置页显示版本标识。本仓库未创建正式稳定发布；main 也不能单独作为稳定性证明。许可证、私密安全报告渠道和试用验收仍待后续处理。

## 可核对的安装包

```sh
npm test
npm run check
npm run package -- --channel test
```

`dist/` 同时生成同版本的 `.zip`、`.sha256` 和 `.json`。ZIP 只收录 extension 中允许的源码文件，拒绝符号链接和未知类型；清除文件时间、权限和枚举顺序造成的差异，相同源码在相同打包环境中产生一致字节。

JSON 包含版本、构建渠道、源提交、工作区是否有未提交修改、文件数、大小和 SHA-256。未提交构建会如实标记 `sourceDirty: true`，不能将其提交编号当作完整源码证据。SHA-256 用于核对包与校验文件，不是维护者签名，也不证明来源可信；应从同一可信版本来源取得文件。

```sh
cd dist
shasum -a 256 -c ai-memory-collector-0.4.14.sha256
```

CI 对提交运行测试、静态检查和测试打包，上传名称含提交编号的测试产物，包括三个文件。它不自动创建 GitHub Release、不合并 PR，也不发布到浏览器商店。

## 小范围试用交付

维护者向试用者交付固定提交的测试包，并附上 [操作卡](pilot-guide.md)、[空白验收表](pilot-results.md)、隐私说明和升级指南。安装包、来源 JSON 与说明必须来自同一提交；提供整个试用包的文件清单和 SHA-256，包名包含版本及提交前缀，避免相同版本的说明修订被混淆。

外层试用包不是可直接加载的扩展。先解压外层包，再将其中的 `ai-memory-collector-版本.zip` 解压到固定安装目录，加载含 `manifest.json` 的目录。升级已有安装时沿用原路径，不另装一份。

每轮记录浏览器、操作系统、起止扩展版本和来源提交。只有同一固定提交收齐的真实试用结果才能用于该轮结论；后续分支上的代码不自动继承“已验收”。试用包不包含个人归档、浏览器配置、诊断原件或 Token。准备包和记录表不等于已完成 5–10 人试用。

## 渠道和升级

- 无参数打包标记为 `development`；`--channel test` 标记为测试构建。
- `--channel stable` 只允许干净 Git 工作区、HEAD 上匹配版本的 `v版本号` 标签，且 manifest 不含开发版 `version_name`。这些是防误标门槛，不替代完整验收或发布审批；当前开发版不能以 stable 打包。
- Mac 更新器默认 main，`--test` 每次显式选择 `feat/automatic-collector-v2`。先取得该分支的提交，再下载固定提交。脚本拒绝自动降级，并在原路径备份后更新；具体用法见 [Mac 更新指南](macos-update.md)。
- ZIP 和来源文件归档后可保留固定版本；不要仅依赖随时可能推进的分支下载链接。
- 更新不卸载扩展，保留安装目录和扩展身份；代码回退不等于浏览器数据格式回退。

## 正式发布仍需完成

确定许可证和安全报告渠道，完成首次安装、无变化检查、停止重启、升级和目录迁移的真实试用验收，再决定稳定版本标签、Release 附件和下载入口。当前版本不自动执行这些步骤。
