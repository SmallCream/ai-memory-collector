# P0 安装与试采集

P0 用于验证接入条件。它不是正式自动备份工具；采集后请实际打开 JSON 与 Markdown 核对。

## 1. 安装

1. 在代码仓库点击 **Code → Download ZIP**，解压到一个固定文件夹。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 开启右上角“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择解压后的 **extension** 子文件夹，它里面应直接包含 `manifest.json`。
5. 在浏览器工具栏固定 AI Memory Collector。点击图标打开采集台；再次点击会回到已有页面，不重复新建。

无需运行服务器或构建命令；无需安装 Node、Git 或 Python。P0 清单最低版本为 Chromium 120，实际浏览器兼容性仍需实测。

源码更新后，覆盖**原加载路径**中的 `extension/` 内容，在扩展管理页点击“重新加载”，关闭旧采集台后再从图标打开。更新使用原浏览器配置，不要卸载或换到新目录重新安装。请先保存旧采集台里的待保存副本。只要扩展身份和存储仍在，设置、目录句柄与暂存可恢复；目录权限可能仍需再次授权。

macOS 用户可以改用 [双击更新脚本](macos-update.md)：只需取得一次 `update-macos.command`，首次选择上面这个原加载目录，以后双击脚本更新，再点浏览器的“重新加载”。脚本不需要访问你的浏览器资料、GitHub Token 或对话文件。

0.1.4 会自动记住仓库、分支和详情接口，不必先连接 GitHub 成功。勾选“在此浏览器记住 Token”后也会恢复 Token；首次升级仍需补填一次旧版未保存的 Token。确认页面显示“设置已保存”或“设置与 Token 已保存”后再关闭或更新。

点击图标只聚焦已有采集台，不改变正在处理的来源。要采集另一个 ChatGPT 标签页，请在采集台重新选择来源并识别账号。账号核验、个人空间确认与列表位置不作为永久设置恢复。

## 2. 验证账号与列表

1. 在 ChatGPT 网页登录，并切换到**个人空间**。先新建一条不含私密信息的普通测试对话。
2. 在采集台点击“授权并查找标签页”，批准访问 `chatgpt.com`，选择对应标签页。
3. 勾选个人空间确认，点击“识别当前账号”。
4. 显示名称与哈希账号标识后，点击“读取第一页”；必要时点击“读取下一页”。每页最多 20 条。
5. 如果只想验证详情或列表不可用，可在网站打开测试对话后，点击“使用当前页面对话”。它只从页面地址取得 ID，不代表列表接口验证通过。

身份取自当前登录会话，哈希用于原型目录归属；显示名称不决定身份。本版不验证团队工作区或自动绑定已有数据仓库账号。试采集期间不要切换账号和空间。

请求前后会复查身份；可以拦截观察到的账号变化，但不能声称已覆盖快速 A→B→A 切换或工作区切换。正式 run 与会话失效管理属于 P2。

## 3. 验证详情

选择一条对话，点击“采集所选对话”。默认使用“分页消息列表”接口；若返回 404 或格式不匹配，展开“采集选项”，手动换“消息树”接口再试。接口选择会自动记住，程序不静默切换接口或绕过验证。简短结果显示在按钮下方，原始采集摘要可展开“查看采集详情”查看。

实验接口依据公开项目的实现说明，未经当前账号实测；网站变化时可能失效。登录、403、404、限流、HTML 验证页和结构变化都会明确显示，不当作空对话或删除。

分页列表模式只保存这一次取得的响应，保留 `page_info`，不拼接未获取的页面；消息树模式保留完整响应中的 `mapping` 和未知字段。两种模式均标记分支与消息完整度未验证。

采集结果经归档处理后先暂存在扩展 IndexedDB。单响应上限 8 MiB、待保存文件组上限 10 MiB；超限明确停止，P0 不处理大型全量归档。认证元数据与带凭据的结构化附件 URL 会脱敏并记录位置，正文和代码不因包含“token”等词而改写。

## 4. 验证真实本地保存

1. 新建一个空文件夹，例如 `collector-p0-test-01`。
2. 点击“选择测试目录”，授权该文件夹。
3. 点击“保存 JSON 与 Markdown”。成功状态需包含写入后的读回核对。
4. 到该文件夹查看 `p0-captures/chatgpt/<哈希账号标识>/` 下的 JSON、Markdown、清单和账号说明。
5. 对照网页核对 Markdown 中的对话正文、表格和代码；采集摘要与 `archive/manifest.json` 记录消息数量、覆盖范围和分支说明。

0.1.3 起，Markdown 只展示对话标题、发言人和正文；采集元数据与原生结构保留在 JSON 和清单中。阅读版省略系统、工具等明确的内部消息，附件使用简短占位提示。示例见 [Markdown 阅读效果](markdown-example.md)。

旧 Markdown 与扩展内的旧暂存不会自动转换。更新扩展后，先确认旧结果已保存，再清除旧暂存，重新采集并保存到新的空测试目录，即可查看新版排版。

关闭采集台后重新打开，可恢复待保存副本和目录句柄；若目录权限失效，点击“恢复目录权限”。重新保存完全相同的文件不会重复写入。确认文件已保存后，可点击“清除本机待保存副本”开始下一次试采集。

**本版不覆盖任何不同内容。** 换一条对话、标题改变、重复采集生成不同清单、文件被手工修改或上次留下不同的残留文件时，请另选一个空测试目录。正常稳定目录、增量更新、清单合并和迁移属于 P1。P0 也不读写现有生产 `data/` 目录。

文件组不是跨文件原子事务；失败后可能留下部分文件。相同已完成文件可安全重试，遇到不同内容就停止。写入期间不要用其他程序修改目标目录。

清除暂存不会删除本地文件。直接卸载扩展可能丢失尚未落盘的暂存，请先保存。

## 5. 验证 GitHub

推荐先用专用私有测试仓库。也可使用自己的私有数据仓库；本操作会新增 `collector-probe/connection-check.json` 和一条提交，不修改其他路径。

1. 创建或选择一个**私有**仓库。不要使用公开的插件代码仓库。
2. 在 GitHub 创建仅授权该仓库的细粒度 Token，给 Contents 读写权限。分支保护或组织审批要求需按实际仓库配置处理。
3. 采集台填写 `用户名/仓库名`；分支可留空使用默认分支。
4. 填写 Token，点击“检查仓库连接”，授权 `api.github.com`。
5. 点击“写入并读回测试文件”，然后到 GitHub 检查上述文件。

测试文件仅含产品名、版本和 synthetic 标识，不包含对话、账号身份、设备信息或 Token。默认不记住 Token，关闭或刷新后需重新填写；显式勾选“在此浏览器记住 Token”才会保存在本机扩展存储中，不写入归档、不传给 ChatGPT，也不通过浏览器同步到其他设备。本机持久化不等于加密保险箱。

取消勾选会移除已持久保存的 Token（当前输入可继续本页使用）；“清除已保存 Token”会同时清空当前输入。以页面显示清除成功为准，存储失败时需重试。清除扩展中的 Token 不会撤销 GitHub 上该 Token 的授权。

文件已存在且内容相同时返回“已有相同文件”，本次不写入，因此不能用它证明当前 Token 具有写权限。已有不同内容则拒绝覆盖。提交超时或竞争时尝试读回，不盲目重复写。

空仓库只初始化默认分支；已有仓库的分支必须预先存在。正式批量提交、下载仓库、三方合并和真实对话上传属于后续阶段。

## 6. 反馈结果

0.1.1 起，每个区域的按钮下方都会显示处理进度、结果或错误代码。遇到点击无反馈或 GitHub `NETWORK` 时，先检查页面右上角版本是否为 0.1.4；该版本包含此前的原生 `fetch` 调用上下文修复。更新后要在扩展管理页重新加载，关闭旧采集台再从扩展图标打开。若显示 `STARTUP_FAILED`，请确认更新了完整 `extension/` 文件夹，且不是直接双击本地 HTML 打开。

更新后仍出现 `NETWORK` 时，在同一浏览器打开 `https://api.github.com`，记录能否看到 JSON 响应。若能打开但扩展仍失败，在采集台按 F12，选择 Console，重新点击“检查仓库连接”，只反馈错误名称和错误代码；不要复制 Token、请求头或完整网络抓包。`NETWORK` 本身不能判断 Token 是否有效。

GitHub 显示成功但提示“本机未能记住设置”时，远端操作已经完成，本机设置需重试保存。固定连接测试文件的内容格式保持 0.1.0，不随界面补丁更新，避免已存在的相同验证文件被误判为冲突。

记录浏览器名称与版本、操作步骤、界面状态和错误代码即可。不要上传 Token、完整网络抓包、真实账号标识或私密对话。可以用新建的虚构对话复现普通文本、代码、多轮、编辑和重新生成的情况。

接入结果写入 [验证记录](validation.md) 后，再决定 P1 的实现范围。
