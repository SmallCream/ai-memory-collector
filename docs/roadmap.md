# 开发路线图与验收

当前开发版本为 **0.4.1**，重点是本地归档的完整性、可恢复性、普通链接与附件的区分及失败诊断。以下区分“源码中实现”和“真实环境验收”；模拟测试通过不代表已在目标网站和用户设备上通过。

当前安装与操作以 [README](../README.md) 为准，检查结果与历史变更见 [验证记录](validation.md)。[0.2 指南](v0.2-guide.md) 是旧版记录，不代表当前设置、附件范围或恢复能力。

## 本轮已实现

0.4.1 新增豆包账号核验、普通列表与消息链分页、独立渲染、原图来源识别及平台隔离。真实账号、列表和正文落盘已验证，附件下载与全账号初始化仍在验收；不承诺豆包项目、归档、历史分支和任意附件覆盖。

| 能力 | 当前实现范围 | 仍需验证 |
| --- | --- | --- |
| 本地优先配置 | 新安装默认定时采集、本地附件下载；GitHub 自动上传与自动恢复分别选择，默认关闭 | 新安装、旧版升级与目录授权的真实浏览器体验 |
| 升级兼容 | 保留账号、目录、任务；原云同步开关迁移为原有上传和恢复行为，旧附件上传开关忽略 | 真实旧用户配置迁移，开关变更期间的在途任务 |
| 对话与真实附件归档 | 原生 JSON、派生 Markdown、受支持图片和文件实体；文件摘要、账号归属及写入恢复 | 剩余失败附件的真实来源，长对话与网页格式变化 |
| 每条对话完整性 | 区分正文、已识别附件中已保存、外链、失败、内部缺失、暂不支持和按设置暂停 | 真实对话统计与文件落盘情况一致，不误报全账号完整 |
| 本地缺失补齐 | 约每 24 小时分批检查；缺失 Markdown 从核对后的 JSON 重建，缺失实体附件加入补采；手动入口可提前检查 | 重启中断、目录失权、文件移动/删除、手工修改保护 |
| 增量采集 | 按 ID、更新时间、标题跳过未变详情；可靠消息数组可复用历史前缀，保留完整复核 | 手机更新、编辑/重新生成、长分页与多标签页 |
| 跨轮次失败处理 | 失败次数与来源版本持久化，暂时错误冷却；需要适配或处理的错误等待条件恢复或手动重试 | 限流、登录过期、来源失效、同错误持续多轮 |
| 请求取消与调度 | 暂停/账号变化取消采集器详情和平台附件请求；账号任务分别推进，文件写入继续受保护 | 真实浏览器取消回执、迟到响应、后台挂起；匿名外链检测仍有 15 秒时限 |
| 可选 GitHub 备份 | 仅上传对话 JSON、Markdown 及清单，附件不上传 LFS；手动备份独立于自动开关 | 私有测试仓库、已有远端附件保留、上传中途改变设置 |
| 云端恢复 | 自动恢复独立开关；只含对话的备份明确报告云端缺少附件，保留本地冲突 | 新电脑、跨设备版本及从原平台补采附件 |

已有待上传的有效记录会保留；关闭自动上传后的新本地采集不再为每条对话重复维护完整待上传正文副本。以后开启上传或手动备份时，从核对后的本地归档分批建立上传任务，无需全量重新抓取网站。

## 必须完成的真实环境验收

1. **纯本地使用：** 全新安装不配置 GitHub，完成账号绑定、目录选择、初始化、增量与附件保存；主页不出现无关待上传警告。
2. **开关独立性：** 关闭本地附件自动下载后正文继续保存；手动补齐可明确安排尝试。含附件对话的 JSON/Markdown 可单独上传。
3. **完整性与修复：** 使用正文、图片、ZIP、PDF、外链和暂不支持附件的样例，核对界面计数；删除一份派生 Markdown 或已保存附件，验证补齐；人工修改和异常文件保持保护。
4. **增量与重复运行：** 手机新增/续聊、标题变化、编辑和重新生成后只更新同一归档；未变化详情跳过；分页衔接不可靠时保留旧档。
5. **中断与恢复：** 断网、限流、关闭源标签页、电脑休眠、浏览器重启、目录失权与恢复；任务保留而不是要求清空数据。
6. **账号与取消：** 同账号多标签页、A/B 账号切换、长请求期间暂停，确认取消后迟到数据不会写入错误账号；文件保存阶段完成一致性收尾。
7. **旧版本升级：** 沿用原扩展路径升级；已有自动上传与自动恢复保留，旧附件上传配置忽略，关闭操作在权限失效时仍可保存。
8. **可选云备份：** 在独立私有测试仓库验证纯文字备份、附件本地缺失提示、手动备份、仅恢复模式、双设备同对话更新与冲突保留。

真实验收尚未全部完成，之前的附件下载失败或 GitHub 提交错误不能因本版功能加入就标记为已解决。每次实测记录浏览器版本、扩展版本、日期、覆盖范围、结果和限制；公开记录仅使用虚构或充分去标识的数据。

## 当前边界

- ChatGPT 接入个人空间普通对话列表；项目、归档、临时和团队空间尚未完成范围验证。豆包普通消息链已接入，扩展实机验收待完成；Gemini、DeepSeek 尚未接入。
- Markdown 展示可读的当前分支。原生 JSON 保留平台实际返回的消息树或数组；当前分支数组不等于全部分支。“正文完整”不代表账号全部历史或全部附件已获取。
- 支持常见栅格图片、ZIP、PDF、DOCX / XLSX / PPTX 及常见文本，单附件上限 **16 MiB**；音视频、旧版 Office、HTML 和其他未适配格式尚不保证实体归档。
- 公开外链默认保留链接，未下载的外链不是完整离线备份。网站已删除、过期或无权限的来源不保证可以恢复；404 不触发本地删除。
- 本地检查以存在性和大小为主，不是每天全量哈希校验。同大小内容变化通常在读取基线、修复或上传时再核对。
- 日常列表仍完整分页核对，尚未实现“近期轻扫＋低频全列表核对”。7 天或 20 次后的完整复核针对已使用消息尾部复用的归档，不是所有历史对话的统一重抓。
- 同账号任务仍顺序处理；暂停不是强制中断所有磁盘写入或任意网络请求。匿名外链检测当前保留 15 秒超时。
- GitHub 只备份对话时，新电脑无法从仓库还原未上传的二进制附件，Markdown 中本地图片链接可能无法显示。
- 不提供独立搜索阅读器、AI 记忆提炼、跨平台上下文导出或 ChatGPT 桌面端原生会话导入。

## 持续保留的标准

- 按稳定账号身份隔离写入，同名昵称不混写。
- 同一对话一组规范 JSON/Markdown 路径，续聊和标题变化不重复建档。
- 部分详情、列表缺失、失败与 404 不覆盖完整旧归档或触发删除。
- 正文落盘、附件落盘与云备份分别计数；发现缺失后不能仍声称实体已存在。
- 文件写入与清单更新保留恢复记录，已有有效待交付数据不能因开关变更直接丢弃。
- 人工修改、来源版本不确定与远端竞争保持保护，不强制覆盖或更新远端分支。
- 文档、界面和验证记录明确区分已实现、模拟通过、实际通过和暂不支持。
