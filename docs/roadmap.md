# 开发路线图与验收

当前开发版本为 **0.2.0**。以下区分“源码中实现”和“真实环境验收”；模拟测试通过不代表已在目标网站和用户设备上通过。

安装与操作见 [0.2 指南](v0.2-guide.md)，程序检查与实测状态见 [验证记录](validation.md)。

## 当前限制

- ChatGPT 网站内部接口和工作区语义尚未形成稳定契约。第一版只针对个人空间普通列表；项目、归档、临时和团队空间保持未验证状态。
- 消息树能检查结构和已返回分支；消息列表缺少明确分页结束标记时停止该条归档，不用猜测请求参数补页。
- 附件实体下载、网页无法访问的已删除对话恢复、新设备整个仓库下载尚未提供。
- 旧 P0 归档与未保存副本保留，不自动转换为正式归档或上传。
- 本地人工编辑与少数无法判定的冲突仍可能需要查看提示处理，不能承诺所有冲突自动合并。

## 下一轮验收

1. 在实际 Chrome / Edge 完成首次引导，确认授权、目录写入、真实 GitHub 提交与状态一致。
2. 用普通、长对话、编辑和重新生成的无敏感样例核对原文、JSON、Markdown 和实际消息范围。
3. 同账号多标签页，以及 A/B 两账号往返切换，检查任务归属和迟到响应处理。
4. 覆盖断网、限流、关闭源标签页、后台挂起、浏览器重启、目录失权与恢复。
5. 用独立测试数据仓库进行两台电脑同 ID 首建、同对话同时更新和提交竞争测试。
6. 验证无变化不重复写入、缺少派生文件能补齐、部分完成不误报为全量完成。

## 后续开发

| 方向 | 下一步 |

| 接入稳定性 | 根据真实响应适配详情分页与不同网站版本，补充去标识样例 |

| 安装与更新 | 保持原路径更新体验；完成许可证、兼容矩阵和正式发布准备 |
| 数据使用 | 另行讨论记忆提炼、共享读取、检索展示；不混入当前采集任务 |

## 必须保持的验收标准

- 账号按稳定身份隔离，昵称相同也不混写。
- 同一对话只有一组规范 JSON / Markdown 路径，续聊和标题变化不重复建档。
- 失败、列表缺失、部分详情、404 不删除或覆盖完整旧归档。
- JSON、Markdown、清单核对成功后才能报告本地完成；GitHub 结果单独确认。
- 同一账号的初始化、增量、补采不并行写入；中断后的任务有持久恢复记录。
- 不强制更新远端分支，不因本机时间较新就覆盖来源版本，不静默丢弃人工改动。
- 文档、界面和验证记录明确区分已实现、模拟通过、实际通过和暂不支持。

每次实测记录浏览器版本、扩展版本、日期、覆盖范围、结果和限制。公开记录只使用虚构或充分去标识的数据，不包含原始账号身份、对话正文或认证信息。
