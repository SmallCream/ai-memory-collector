# 第一阶段：对话采集、归档与同步设计

设计基线：6.0，2026-10-20。本文是既定采集方案的代码仓库版本，所有能力仍需按[路线图](roadmap.md)验证。示例账号、路径和 ID 均为虚构。

## 1. 范围

本期包括账号绑定、列表发现、详情获取、原生 JSON、派生 Markdown、真实本地目录、GitHub 同步、异常恢复和状态界面。

首版目标为桌面 Chrome / Edge、ChatGPT 网页端。客户端本地文件采集、其他平台适配、官方导出批量导入、跨平台转换、附件实体备份、平台内置 Memory、记忆提炼和共享读取留到后续。

浏览器扩展独立运行，不要求安装本地程序、Git 或自建服务。网站标签页、身份和运行环境可用时采集；休眠、关闭浏览器或登录失效期间不承诺定时任务执行。

## 2. 模块与处理顺序

| 模块 | 职责 |
| --- | --- |
| 平台适配器 | 身份核验、能力说明、列表和详情读取、原生结构解释 |
| 账号与批次 | 绑定、范围、开关、任务归属和 run_id 失效 |
| 调度与队列 | 触发合并、分页、持久载荷、重试、限流与恢复 |
| 比较与合并 | 消息身份、内容变化、覆盖范围、源版本和三方比较 |
| 归档 | 稳定文件路径、共享元数据和 Markdown 生成 |
| 本地文件 | 目录权限、外部改动检测、版本写入和恢复 |
| GitHub | 下载、按账号组织提交、竞争检测、版本确认 |
| 界面 | 首次配置、范围、进度、能力限制和集中处理事项 |

正常路径：身份核验 → 列表发现 → 详情获取 → 可靠暂存 → 版本比较 → JSON 与归档说明落盘 → 生成 Markdown → 远端合并 → 提交文件组 → 确认本地和远端版本。

远端合并改变 JSON 时，重新生成 Markdown，并把最终版本落实到本地。采集队列与保存上传队列分开；同一对话文件更新串行，同一仓库提交串行。

## 3. 账号与会话

账号的显示名称便于辨认，不能代替平台原生身份。绑定记录保存 platform、固定 account_key、已核验原生身份、display_name 和 data_path；设备级登录状态和凭据不放入归档。

对话唯一键为 `platform + account_key + conversation_id`。只有平台 ID 确实按工作区划分作用域时才加入 workspace_key；标题变化或移动项目不应新建档案。

已绑定不代表已登录，也不代表具备列表或详情能力。无法可靠核验身份时不启动全账号采集。

| 事件 | 规则 |
| --- | --- |
| A 切换到 B | 废止 A 的 run，尽力取消请求；核验 B 后创建新 run |
| B 切回 A | 新建 A 的 run，利用检查点继续，不复活旧在途请求 |
| 退出登录或身份不明 | 停止新请求；归属不明的响应不进入归档 |
| 关闭某账号同步 | 停止新采集和上传，保留文件与待办，不撤销已完成提交 |

任务创建时固定账号、工作区、对话 ID 和 run_id。请求前、响应进入可靠暂存前再次核验；取消网络请求不能替代迟到响应检查。

切换前已经核验并可靠暂存的完整数据，可继续沿原账号路径保存和上传，前提是该账号同步仍启用。

同一插件实例、同一平台只运行一个当前账号采集批次；多标签页去重。不同浏览器配置和电脑使用独立运行状态及本地目录，通过 GitHub 汇合。

## 4. 平台接入

优先使用平台明确支持且授权范围匹配的接口。网页内部接口需逐项验证认证、访问范围和返回结构，不在文档中预设未经验证的内部 URL。

原型验证内容脚本中的同源请求；浏览器 Cookie 与网站自行设置的 Authorization、CSRF、工作区参数分别处理，不能假定复制全部 headers 即可长期重放。确需页面内状态时才增加最小桥接，只允许白名单操作，不接受任意 URL 或写入路径；GitHub 凭据不进入网页。

内部适配器契约：

| 操作 | 必须说明 |
| --- | --- |
| identifyAccount | 稳定身份、核验依据，以及未登录/失败/不确定的区别 |
| getCapabilities | 列表范围、分页、时间语义、分支和附件的已验证能力 |
| listConversations | ID、标题、可用时间、分页游标和实际范围 |
| getConversation | 原生载荷、来源格式、源版本、生成状态与覆盖说明 |
| observeCurrentConversation | 回复完成、编辑、分支变化等复读信号 |
| compare / renderMarkdown | 本平台结构比较与可读展示 |

普通、项目、归档、临时会话等分区分别报告覆盖情况。页面内容读取是显式降级能力，只归档已加载内容并标记部分覆盖，不声称已补扫全部账号。

开发者 Conversations API 不等同于 ChatGPT 网页历史入口。各能力区分计划、原型可用、已验证和暂不可用，并记录适配器版本与验证日期。

## 5. 发现与扫描

默认在用户选择的范围内先处理最近 30 天，之后低优先级补齐可访问历史。用户可以选择仅近期或排除对话、项目。

| 触发或参数 | 建议默认值 |
| --- | --- |
| 首次绑定 | 一条对话试采集通过后启动近期扫描和历史补抓 |
| 启动、网站打开、登录或网络恢复 | 核验身份后补做到期任务，合并重复触发 |
| 列表扫描 | 账号可用时约每 15 分钟 |
| 普通事件冷却 | 约 5 分钟，不阻挡切换后的身份核验 |
| 当前对话变化 | 完成或明确中断后约 10 秒防抖复读详情 |
| 增量重叠窗口 | 约 10 分钟，前提是源时间与分页语义可靠 |
| 历史巡检 | 每周安排一轮，在线分批推进并轮换详情复查 |
| 来源请求并发 | 每个平台默认 1，按限流和实测调整 |

扫描游标和水位按设备、账号、范围保存。对应列表范围完成且候选详情已持久入队后才能推进水位；详情失败留独立待办。不能遇到第一个旧 ID 就停止分页。

时间不可靠时改为分页核对与轮换详情检查，并显示发现能力受限。手机端变化由后续主动扫描发现。浏览器恢复时重建必要定时器，不依赖后台进程常驻。

## 6. 归档格式和路径

### 6.1 JSON 主档与派生 Markdown

一份逻辑对话保存一组同名 `.json`、`.md`。JSON 是原文主数据，Markdown 由已确定版本生成，不独立双写正文；归档说明记录格式、身份、覆盖范围和内容指纹。

保留各平台原生结构，不强制套用 ChatGPT 结构。ChatGPT 网页响应先标记为 `chatgpt-web-detail`；只有与官方导出样本验证兼容后，才使用 `chatgpt-export`。经验证的导出格式可以用单元素数组保存一条完整对话，不虚构平台 schema 版本。

保留消息 ID、内容块、父子关系、分支、空根节点、工具消息、未知业务字段和附件引用。认证信息不属于原文；临时带凭据的下载 URL 不作为长期附件引用。去除敏感认证字段时记录处理，不声称字节级无损。

列表、消息、分支和附件覆盖分别记录。当前分支完整不代表全部分支完整。部分结果不覆盖已有完整版本；尚无档案时可以保存明确标记的部分版本，后续补齐沿用相同身份。

Markdown 是简洁的对话阅读版，只展示标题、发言人和正文，保留正文中的表格、列表和代码块。消息 ID、父子关系和其他分支留在原生 JSON；源指纹、渲染器版本、覆盖范围与分支说明留在归档清单，阅读正文不展示这些字段。按已知当前分支展示；未知当前分支时不猜测。系统、工具和明确隐藏的消息保留在 JSON，阅读版省略；不能展开的附件使用简短占位提示。

### 6.2 文件命名与共享说明

账号目录示例：`data/chatgpt/demo-account/`。

| 相对账号目录 | 内容 |
| --- | --- |
| account.json | 稳定账号标识、显示名称、目录绑定，不含凭据 |
| conversations/2026/10/ | 同名 JSON、Markdown 文件组 |
| archive/manifest.json | 按唯一键登记路径、格式、版本指纹、覆盖与来源状态 |
| archive/exclusions.json | 排除和防重新导入的标识，不含对话原文 |
| attachments/ | 预留；首版默认保存引用，不自动备份附件实体 |

文件名：`创建时间__首次有效标题__完整对话ID.json`。

例如 `2026-10-20T09-00-00Z__项目讨论__demo-conversation-id.json`。时间统一 UTC，界面按用户时区展示；标题清理不适合路径的字符，默认截取前 40 个字符，另检查整体路径长度。创建时间缺失时用首次发现时间并记录依据。

文件名首次登记后固定，标题或时间补全不自动重命名。身份与文件名分开：优先复用远端已登记路径；两台设备首次归档产生不同路径时，按唯一键归并到有效远端路径。删除旧本机路径前检查人工改动，有改动先保留恢复副本。

清单按对话条目语义合并；路径、格式和完整度绑定对应 JSON 指纹，不能把完整版本标记套到部分版本上。它是共享归档说明，不是可随时丢弃的搜索缓存。

## 7. 新增、更新、删除和冲突

来源采集比较基准与本地/远端共同同步基准分别维护。消息 ID 判断身份，内容指纹检测变化，可靠源版本判断先后；不能用消息数量、正文哈希或保存时间替代消息身份。

新 ID 建档前查远端登记；续聊、编辑、重新生成、标题变化更新同一档案。按原生分支关系处理，不拼接互斥回复。未变化则不提交；设备扫描时间不参与业务变化指纹。

列表缺失、403、404 或请求失败不证明删除。可靠来源明确删除时标记来源状态，默认保留备份。未采集过的中间编辑版本不保证能恢复。

冲突依次处理：

1. 内容一致时去重。
2. 只有一边相对共同基准修改时，检查身份和完整度后采用修改方。
3. 可以证明互不影响的修改，按原生结构合并。
4. 同一消息内容不同时，优先使用可比较且覆盖冲突内容的可靠源版本。
5. 无法确定时，核验账号后重新读取完整、稳定的线上详情。
6. 临时无法读取或覆盖不足时，保留双方证据，等待自动复查，仅暂停该对话。
7. 长期无法判断或涉及人工修改时集中展示待处理事项。

设备时间、采集时间和 Git 提交时间不能决定原文新旧。整个对话的更新时间只作辅助，可能仅因标题变化而更新。重新拉取只裁决实际覆盖范围，当前分支快照不能抹掉其他归档分支。

A 的复核需要 A 登录时，当前登录 B 就等待 A，不改变任务归属或阻塞 B。先解决 JSON，再重建 Markdown。

## 8. 本地文件、队列和恢复

| 位置 | 内容 |
| --- | --- |
| 用户授权真实目录 | 原生 JSON、Markdown、共享归档说明 |
| 扩展 IndexedDB | 队列载荷、游标、水位、重试、共同基准、指纹和目录句柄 |
| 扩展本机设置 | 仓库授权与设备配置，不进入归档仓库 |
| 私有 GitHub 数据仓库 | 已提交当前文件及历史 |

由用户点击选择真实目录；重启后复查权限，失效时请求重新授权。目标浏览器和扩展执行环境的目录访问必须实测。同一目录只由一个插件实例自动管理。

先把载荷、身份和内容版本可靠暂存，再写 JSON 与元数据，随后生成 Markdown；源指纹、Markdown 指纹与渲染器版本记录在归档清单中。只有文件组匹配才标记本地完成并进入上传。

JSON、Markdown、清单、IndexedDB 和 GitHub 不是跨系统原子事务。各阶段按确定版本记回执并可重放；JSON 已写而 Markdown 未完成时重启补齐，不能只凭文件存在推进完成状态。清单与内容不匹配时保留最后确认组合，按持久任务恢复。

人工修改、移动或删除文件时保护改动，不自动覆盖或当作云端删除；写入前复查指纹，不承诺跨程序锁。暂存软上限建议 100 MiB，并受浏览器配额限制；接近上限暂停新采集，不丢弃未上传原文。

临时错误指数退避并加入随机抖动；429 遵循服务端提示；身份变化结束 run；结构变化停止受影响解析；目录或 GitHub 权限问题保留待办并提示。超时写入先核对结果再重试。

## 9. GitHub 同步与多设备

首次连接下载用户所选仓库的当前快照，保留目录结构，不克隆 `.git` 历史。已有本地内容先比较，不覆盖式初始化。下载到的其他账号资料不自动获得上传资格。

建议有变化时约每 5 分钟组织同步批次，按账号归组，同一仓库串行提交；立即同步仍遵守限流。

1. 读取最新分支提交和树，获取相关清单、JSON 与固定路径。
2. 用共同基准、本地、远端比较，解决路径与 JSON，再生成 Markdown 和说明。
3. 以最新远端树为基础，仅修改本批账号获准路径。
4. 用 Git Trees / Commits / References API 提交同一组 JSON、Markdown 和说明，`force=false` 更新分支。
5. 分支竞争时重新读取、合并、重建提交；不能只替换旧整棵树的父提交。
6. 确认远端结果，把最终版本落实本地，双方一致后推进共同基准；期间的新修改保留待办。

提交超时先查远端是否已包含确定版本。提交 SHA 记录在回执或历史映射中，不预先写入提交自身。共同基准丢失时不能假定一边未改。

写入隔离由插件的身份与路径规则实现，不是 GitHub 提供的账号目录 ACL。其他账号、根配置及既有记忆目录保持不变。不把队列、扫描水位或凭据提交到仓库。

## 10. 配置、权限和保留

首次配置：仓库授权 → 选择真实目录 → 登录网站 → 确认账号与范围 → 一条对话试同步。第二台电脑独立授权并重新核验身份。

GitHub 首版考虑限定到指定仓库的细粒度 Token，按实际接口授予必要权限；分支保护阻止提交时提示，不自动修改保护规则。账号、仓库和目录均可配置。

日常入口复用已有采集台，不因重复点击刷新页面或切换运行任务的来源。普通表单设置在本机自动保存；Token 默认不持久化，只有用户勾选记住后才保存在本机，并提供清除入口。设置保存与采集归档分离，保存配置不代表账号或仓库已验证。原地升级沿用扩展身份与存储，恢复后仍核验当前登录账号和目录权限。

按需申请站点、调度和存储权限；原型决定是否需要额外桥接权限，不默认申请所有网站、cookies、debugger 或 nativeMessaging。

状态分开显示列表发现、详情采集、本地保存和 GitHub 上传；同时展示实际覆盖、等待登录、限流、目录失权、适配器变化和未决冲突。

排除后停止新采集并保留旧档；来源删除默认保留备份。用户要求删除归档时明确范围并记录防重新导入标识；删除当前文件不等于清除 Git 历史或其他设备副本。

诊断默认不含正文与凭据。直接卸载扩展时不能保证提示或保留内部未落盘队列；真实目录中已经写入的文件由用户持有。

## 11. 兼容与后续边界

接入已有数据仓库前先只读核对格式。旧 Markdown 不能伪造成平台原生 JSON；保留旧档与来源，能重新获取时按可靠身份关联。迁移需可恢复、可重复，不删除既有记忆或无关文件。

客户端采集、其他平台、批量导入、格式转换、附件实体备份及后续记忆使用只预留扩展接口。本期不要求另装离线校验工具，身份、路径、覆盖、版本等必要检查内置于采集流程。
