# 首次备份、升级与目录迁移验收

0.4.11 在隔离数据上验证以下使用过程，不清空真实扩展存储，不修改用户归档。入口、文件结果和仍需实机确认的范围分开记录。

## 首次备份

1. 在已登录的平台页打开插件，授权该平台，确认并启用账号。
2. 选择独立的归档目录；权限不足时不能完成设置或写入。
3. 选择“仅使用本地备份，继续”，确认自动检查和附件下载设置，点击“开始首次备份”。
4. 完成后分别查看对话结果、附件结果及问题与诊断日志。在所选目录内打开 Markdown；图片通过相对路径引用本地附件。
5. 无新增或变化时再检查一次，完整列表仍会读取，已归档正文应跳过。

验证：真实生产服务、采集引擎、归档、附件和本地检查模块串联；ChatGPT 与豆包的合成正文及图片写入真实临时磁盘。核对账号初始化、文件哈希、Markdown 图片链接、重新创建后台后设置和文件保留，以及再次检查没有新增详情请求或改写归档。另在隔离浏览器页面逐步点击实际面板，使用模拟权限/目录和合成来源，完成首次引导及再次检查。

## 升级

保持原安装目录和扩展身份，备份后更新，重新加载扩展并刷新平台页。不要卸载、清空浏览器数据，或把归档放在插件代码目录中。

验证包含两个层次：

- 更新器运行实际 Shell、ZIP 校验、目录替换与回退，网络及 macOS 专有命令使用受控模拟。覆盖网络失败、非法文件、符号链接、替换失败、进程中断后的原目录恢复、防降级和测试渠道不持久化。
- 使用持久化配置与任务重新创建生产服务，验证旧 schema 配置迁移保留账号、目录、关闭的云上传/恢复、已停止队列和磁盘文件；不把升级当作自动重新采集或开启云同步的授权。

这些结果不代替真实 Chrome 新配置文件安装、原生权限弹窗、浏览器重启后的系统权限保留，以及真实 GitHub 下载验收。

## 目录迁移

1. 停止本轮，等待当前文件保存及其他写入结束。出现未完成写入提示时，先在原目录完成恢复。
2. 复制整个归档根目录到新位置，保留内部结构。先复制、核对后再考虑清理旧目录。
3. 在设置中更改保存位置，选择复制后的同一级根目录。插件不会替你复制旧文件；选择空目录会作为新的保存位置。
4. 执行检查更新，查看本地完整性和附件状态；需要时使用高级操作中的“补齐缺失”。移动文件时保留相对路径，才可离线显示已下载附件。
5. 若目录切换失败，处理原因后重新选择。恢复当前目录权限只恢复访问，不会重试之前失败的目录选择。

验证：完整复制后重新创建服务，正文跳过、文件哈希一致、旧目录未改变；迁移副本缺失 Markdown 时从 JSON 重建，缺失图片时补采后哈希和相对链接恢复；人工修改的 Markdown 保留并报告冲突；未完成写入继续阻止切换。旧目录的检查冷却不阻挡新目录检查，旧目录的附件数量不作为新目录已保存数量。

缺失附件仍依赖原平台可访问，已删除或无权限的来源不能保证恢复。迁移后附件汇总缓存会重新建立，尚无统计不代表全部已保存；可查看当前目录的完整性明细。
