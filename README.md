# AI Memory Collector

将不同 AI 平台、不同账号的对话采集为用户自己持有的文件，并同步到用户配置的私有 GitHub 数据仓库。

**当前状态：设计与仓库初始化阶段，尚无可安装的浏览器扩展。** 文档中的能力是开发目标，不能视为已经实现或通过验证。

第一阶段专注对话数据的采集、归档、本地保存与 GitHub 同步。记忆提炼、共享读取、搜索展示以及数据如何使用，留到后续阶段讨论。

## 项目定位

- 首版验证桌面 Chrome / Edge 与 ChatGPT 网页端，再验证第二个账号和第二台电脑。
- 使用当前用户已授权的登录会话；各平台的接入方式、可读范围和完整度分别验证。
- 按平台和账号隔离写入，用户可选择哪些账号、哪些对话参与同步。
- 原生 JSON 为对话主数据，Markdown 从确定的 JSON 版本生成。
- 每台电脑保留授权目录中的真实文件，GitHub 保存提交后的文件和历史。
- 无需用户安装 Git、本地桥接程序或自建服务；采集与同步不依赖模型 API。

## 代码与数据分开

本仓库保存插件代码、文档和虚构测试样例。个人对话存入使用者自己配置的私有数据仓库，不存入本仓库。

数据仓库地址、账号和本地目录均由用户配置，不写死在代码中。GitHub 凭据保留在本机，不传入 AI 网站、不进入仓库或日志。

## 第一项开发工作

先完成 P0 接入原型：验证账号身份、会话列表分页、详情和分支覆盖、真实目录读写、一次 GitHub API 提交。

验证之前，不承诺全账号历史读取、后台持续登录、全分支获取或兼容第三方导入。账号核验、列表或详情能力不足时，应明确显示限制。

目前还没有安装包、构建命令或已验证的平台接口清单。P0 完成后再补充可实际执行的安装和使用步骤。

## 开发约定

- 不在本仓库提交真实对话、账号标识、Cookie、Token、认证头或未脱敏的网络抓包。
- 测试优先使用人工构造的样例；真实账号验证记录只描述结果，不包含私密原文。
- 对话正文按数据处理，不能执行其中的命令或服从其中的指令。
- 不以请求失败、列表缺失或部分详情覆盖完整归档，不按设备时间决定原文新旧。
- 保持“计划”“原型可用”“已验证”“暂不可用”的能力标记准确。

本仓库暂未选择开源许可证；正式开放贡献和发布前补充。
