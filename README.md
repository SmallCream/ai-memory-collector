# AI Memory Collector

将 ChatGPT、豆包普通对话与受支持附件持续归档到本地。保存 JSON 和可阅读的 Markdown，可选备份对话到自己的私有 GitHub 仓库。无需模型 API Key、自建服务或本地桥接程序。

**当前开发版：0.4.11。** 开发功能位于 Draft PR，尚未作为稳定版发布。新版 Mac 更新器默认读取 `main`，显式使用 `--test` 才读取开发测试分支；两者均按固定提交下载，拒绝自动降级。设置页可查看已安装版本。

## 开始使用

1. 使用对应版本的扩展安装包，解压到固定目录。在 Chrome 的扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，选择含 `manifest.json` 的目录。不要把安装目录当作归档目录。
2. 打开已登录的 ChatGPT 或豆包网页，点击浏览器工具栏的采集器图标，授权对应平台并确认当前账号。
3. 选择自己的归档目录。JSON 和 Markdown 同时保存；受支持附件默认自动下载，单文件上限 32 MiB。
4. GitHub 可以跳过。确认自动采集设置后，开始首次备份。
5. 对话采集结束后，分别查看正文、附件和可选 GitHub 备份的结果。在本地目录打开 Markdown 阅读；复制或迁移时保留整个目录结构。

浏览器需要运行，来源账号和目录权限需要有效。电脑休眠、浏览器退出或平台异常时不能保证按时完成。

## 日常操作

| 操作 | 适用情况 |
| --- | --- |
| 检查更新 | 日常检查；扫描列表后，只读取新增、变化、缺失或仍需重试的对话 |
| 暂停采集／继续采集 | 暂时中断并保留当前队列 |
| 停止本轮 | 结束旧队列；下次检查重新扫描，已保存文件保留 |
| 高级操作 → 补齐缺失 | 检查本地缺失；从有效 JSON 重建 Markdown，并安排受支持附件补采 |
| 高级操作 → 全量补采（需确认） | 重新读取可枚举的全部对话，耗时较长；适用于需要完整复核的情况 |
| 重试失败附件 | 逐项重试附件，不重新扫描整个对话列表 |

首页将结果、问题与诊断入口、日常操作和保存位置前置；确认本地缺失后会出现补齐建议。首次设置默认收起 GitHub 表单，可直接选择“仅使用本地备份，继续”。

暂停／停止对话采集不代表停止独立的 GitHub 备份。手动附件补采也有独立的执行范围。

## 如何看懂结果

- **本轮发现／跳过／新增／更新／待处理**：描述本轮对话检查；“读取了正文”不一定意味着文件发生更新。
- **采集详情中的读取次数**：列表和正文适配器的调用次数，包含重复尝试；一次正文读取可能包含多页网络请求，不等于 HTTP 请求总数。旧任务没有这些计数时显示未记录，新建一轮后统计。
- **附件状态**：单独显示已保存、待处理和未支持资源。正文完成不代表所有附件完成，未授权外链也不等于实体已下载。
- **GitHub 状态**：仅代表对话文件备份或恢复情况，不代表附件已上云。

0.4.8 已减少空闲账号核验；采集和写入前仍核对账号归属。普通检查依赖列表元数据，平台修改内容却不改变时间和标题时可能需要全量复核。

## 遇到问题

从首页点击 **“问题与诊断日志”**，或进入 **设置 → 诊断与日志**。

1. 选择账号，按阶段、结果、时间或错误代码筛选。
2. 展开记录查看失败步骤、原因和处理建议。“本步骤已恢复”只说明这个步骤后来成功，最终结果仍以首页为准。
3. 需要反馈时，点击“预览脱敏导出”，检查内容后保存诊断 JSON。导出不受当前列表筛选影响，覆盖所选账号及仓库恢复的保留记录。

日志在当前浏览器中持久保存。历史展示最近 7 天，每个账号的每类日志最多 200 条、保守大小上限 1 MiB；仓库恢复有独立的一组记录。写入新日志时清理过期历史；清除日志不删除任务、重试记录或归档。旧版本已被覆盖的日志无法补回。

诊断导出使用固定字段和匿名编号，不包含聊天正文、标题、文件名、账号名称、Token、Cookie、原始响应、下载地址或完整本地路径。**不要提交原始 HAR、归档正文、配置文件或凭据。** 反馈入口见 [故障模板](.github/ISSUE_TEMPLATE/bug_report.yml)。

## 支持范围

| 能力 | ChatGPT | 豆包 |
| --- | --- | --- |
| 普通对话 | 个人空间普通列表及当前可读分支 | 网页普通对话、完整消息链分页 |
| 图片与附件 | 已适配的可访问来源 | 已适配来源，含 byteimg.com 原图与文件地址刷新 |
| 常见文件 | 图片、ZIP、GZIP/TAR.GZ、PDF、DOCX/XLSX/PPTX、常见文本 | 同左，含 UTF-8 PowerShell 文本归档，脚本不执行 |
| 项目、归档、团队空间、全部历史分支 | 尚未完成范围验证 | 尚未完成范围验证 |
| 音视频及任意格式 | 不保证下载 | 不保证下载 |

平台内部接口可能变化。无法确认完整性时保留原有归档并报告问题；网站已删除或无权限的资源不保证恢复。平台返回的原始 JSON 不等于账号全部历史已经完整获取。

## 数据保存在哪里

| 数据 | 保存或传输位置 |
| --- | --- |
| 对话 JSON、Markdown、已下载附件 | 用户选择的本地目录，按平台和账号隔离 |
| 账号设置、任务、日志、目录授权句柄 | 当前浏览器扩展的本地存储 |
| GitHub Token | 当前浏览器扩展存储；仅用于配置的 GitHub 操作 |
| 开启 GitHub 备份后的对话 JSON、Markdown 和清单 | 用户配置的私有 GitHub 数据仓库；文件中可能包含个人内容和原始链接 |
| 图片及其他附件实体 | 仅本地保存，不上传 LFS；GitHub 对话备份不能独立恢复完整离线资料 |
| 脱敏诊断 | 用户主动导出到本机，不自动上传 |

详情见 [隐私与数据说明](PRIVACY.md)。

## 安装、升级与回退

升级时保留原扩展安装路径，先备份再替换代码，不要卸载扩展或清空数据；然后在 Chrome 重新加载扩展并刷新来源页面。更新器说明见 [Mac 更新指南](docs/macos-update.md)。

0.4.10 打包同时生成 ZIP、SHA-256 校验文件和提交来源说明；CI 产物明确标为测试版。正式稳定版发布仍待完成。具体命令及边界见 [打包与发布说明](docs/packaging.md)。回退前须确认代码与本地状态格式兼容；有备份不代表任意跨版本回退均安全。

首次备份、升级和目录迁移的操作与验证边界见 [完整流程验收](docs/workflow-validation.md)。
